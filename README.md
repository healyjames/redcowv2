# Venue site

A whitelabel Astro site for hospitality venues. One codebase, one deployed Worker per brand.

Astro 7 (static output) with React islands, TypeScript, and a single server endpoint for bookings. Deployed to **Cloudflare Workers**.

## Getting started

Requires Node 20.

```sh
npm install
cp .env.example .env                                    # set PUBLIC_BRAND
cp .dev.vars.example src/assets/redcow/.dev.vars        # local origin override
npm run dev
```

`.dev.vars` must sit **beside the brand's wrangler config**, not at the repo root — wrangler resolves it relative to that file. Without it the booking endpoint returns `403 Invalid origin` locally, because the committed `ALLOWED_ORIGINS` is the production domain.

## How the whitelabel works

Everything brand-specific lives in one folder:

```
src/assets/<brand>/
├── content/data.ts      business info, pages, opening hours
├── images/              brand photography
├── menus/               PDFs, copied to public/menus by `npm run setup`
├── styles/theme.css     brand theme
├── fonts/               config.ts + subset .woff2 files (see Fonts)
├── logo/ favicon.svg
└── wrangler.jsonc       Worker name, routes, runtime vars, email binding
```

`PUBLIC_BRAND` selects the brand and drives everything else: the `@brand` Vite alias, the generated `tsconfig.json`, the menu copy, the image glob, and which `wrangler.jsonc` the adapter loads. There is no second brand variable.

## Scripts

| Script | Does |
|---|---|
| `npm run dev` | Runs `setup`, then Astro dev inside `workerd` — real bindings, locally simulated |
| `npm run build` | Runs `setup`, then builds to `dist/` |
| `npm run setup` | Writes `tsconfig.json`, copies brand menus, regenerates `src/worker-configuration.d.ts` |
| `npx astro check` | Typecheck |
| `npx astro dev stop` | Stops the dev server and clears its tracked process |

### If the dev server won't start

Astro tracks the dev server by PID, and that state can go stale after a crash or a killed terminal — you get `Dev server already running at http://localhost:4321 (pid …)` while nothing is actually listening, and `curl` returns nothing. Clear it with:

```sh
npx astro dev stop
```

`npx astro dev status` shows what Astro currently thinks is running, and `npx astro dev logs` tails the server output when it's running detached.

## Configuration

| Where | What | Notes |
|---|---|---|
| `.env` | `PUBLIC_BRAND`, `PUBLIC_SITE_URL` | Build-time; inlined into the bundle |
| `src/assets/<brand>/wrangler.jsonc` | `EMAIL_FROM`, `EMAIL_FROM_NAME`, `EMAIL_ADMIN`, `ALLOWED_ORIGINS`, routes, `send_email` binding | Runtime; committed, non-sensitive |
| `src/assets/<brand>/.dev.vars` | Local overrides | Git-ignored |
| Worker → Settings → Build | `PUBLIC_BRAND`, `PUBLIC_SITE_URL`, `NODE_VERSION` | Build variables, per Worker |

Build-time and runtime values cannot substitute for each other: `PUBLIC_*` is inlined at build time, and wrangler `vars` only exist at runtime.

## Email

Bookings send two emails (admin notification, customer confirmation) through the **Cloudflare Email Service** `send_email` binding — no SMTP, no API key. The sending domain must be onboarded in Email Service before customer confirmations to arbitrary addresses will work.

### Testing email locally is safe

`npm run dev` does **not** send real email. The `send_email` binding runs against miniflare's local simulation, which writes each message to disk instead of delivering it:

```
.wrangler/tmp/email/miniflare-<id>/email-html/<id>@<domain>.html
.wrangler/tmp/email/miniflare-<id>/email-text/<id>@<domain>.txt
```

Open the `.html` file in a browser to review the rendered template — the easiest way to iterate on email design. The dev server also logs a summary (`send_email binding called with MessageBuilder: From / To / Subject`) plus the file paths.

This works **before** the sending domain is onboarded, so the whole booking flow can be tested on day one.

> Local simulation applies because the binding has no `"remote": true` in `wrangler.jsonc`. If you ever add that flag — or run a command that forces remote bindings — sends become real and go to real inboxes. Set a throwaway `EMAIL_ADMIN` in `.dev.vars` before doing so.

**Field names are not validated.** The booking payload is cast, not parsed, so a mismatched field name renders as `undefined` in customer-facing email rather than failing. The expected fields are `firstname`, `surname`, `guests`, `date`, `room`, `nights`, `number` (not `phone`), `email`, `additionaltext`. Check a captured `.html` after changing the form.

## Deploying

Each brand is a separate Worker in Cloudflare **Workers Builds**, all connected to this repo on `main`:

| Setting | Value |
|---|---|
| Build command | `npm run build` |
| Deploy command | `npx wrangler deploy -c dist/server/wrangler.json` |
| Build variables | `PUBLIC_BRAND`, `PUBLIC_SITE_URL`, `NODE_VERSION=20` |

The deploy config is generated by the build, so the path is the same for every brand — `PUBLIC_BRAND` already chose which brand it describes.

## Fonts

Every brand has exactly two font slots, `primary` (body text) and `secondary` (headings, buttons). Shared components never name a font; they use `var(--font-primary)` and `var(--font-secondary)`, which Astro's [Fonts API](https://docs.astro.build/en/guides/fonts/) defines for the active brand.

```
src/assets/<brand>/fonts/
├── primary.ttf        source font (not shipped)
├── primary.woff2      generated, Latin subset (shipped, preloaded)
├── secondary.ttf
├── secondary.woff2
└── config.ts          tells Astro about the two .woff2 files
```

`astro.config.ts` imports `src/assets/${PUBLIC_BRAND}/fonts/config.ts`, and `base.astro` preloads both fonts. Astro also generates a size-matched fallback font so the page doesn't jump when the real font loads.

### Setting fonts for a new brand

1. Put the brand's two variable `.ttf` files in `src/assets/<brand>/fonts/` as `primary.ttf` and `secondary.ttf`. Use variable fonts, since the weight range is what keeps files small.
2. Generate the `.woff2` files. This needs Python with `fonttools` and `brotli` (`pip install fonttools brotli`). The last two numbers are the lowest and highest weight the brand actually uses, and must sit inside the font's own weight range:

   ```bash
   python scripts/subset-fonts.py src/assets/<brand>/fonts/primary.ttf src/assets/<brand>/fonts/primary.woff2 400 700
   python scripts/subset-fonts.py src/assets/<brand>/fonts/secondary.ttf src/assets/<brand>/fonts/secondary.woff2 400 700
   ```

   The script keeps Latin characters, `£`, `€`, curly quotes, dashes and arrows. If a brand needs other characters, add them to `UNICODES` in the script first.
3. Copy `src/assets/redcow/fonts/config.ts` into the new folder and change four things per font:

   | Field | What to set |
   | --- | --- |
   | `fallbacks` | `"serif"` or `"sans-serif"`, matching the font's style. Astro measures it to build the fallback |
   | `weights` and `weight` | The same range you passed to the script, as a string such as `"400 700"` |
   | `src` | The new brand folder's `.woff2` path |
   | `name`, `cssVariable` | Leave as they are: `PrimaryFont` / `--font-primary` and `SecondaryFont` / `--font-secondary` |

4. Run `npm run build` and check the built page has two `<link rel="preload" ... .woff2>` tags and that headings and body text render in the new fonts.

If a new brand uses a weight outside the range in `config.ts`, the browser quietly clamps it to the nearest weight, so text looks lighter or heavier than intended rather than breaking.

## Security headers

`public/_headers` is copied into the build and picked up by Workers static assets, so it needs no Cloudflare dashboard setup. It adds these headers to every static response (all pages and `/_astro/*`). The build merges it with the `/_astro/*` cache rule the adapter writes into the same file.

| Header | Effect |
| --- | --- |
| `Strict-Transport-Security: max-age=300` | After one HTTPS visit, browsers refuse plain HTTP to the site for 5 minutes. Kept short so a mistake can't lock anyone out; raise it once everything is confirmed. |
| `X-Content-Type-Options: nosniff` | Stops browsers guessing a file's type, which blocks a class of content-confusion attacks. |
| `Referrer-Policy: strict-origin-when-cross-origin` | Other sites only see the domain, not the full page URL, when someone clicks out. |
| `X-Frame-Options: SAMEORIGIN` | Other sites can't embed these pages in a frame. The site's own iframes of other sites still work. |
| `Cross-Origin-Opener-Policy: same-origin` | Isolates the page from windows opened by other sites. |
| `Content-Security-Policy-Report-Only` | The browser logs a console warning for anything outside the allowed sources but blocks nothing. It allows same-origin files, inline scripts and styles, the Google Maps embed and the booking iframe. |

### Limits

- Responses generated by the Worker script, such as `/api/booking`, don't pass through `_headers`.
- Zone-wide HSTS and the HTTP-to-HTTPS redirect are Cloudflare dashboard settings: **SSL/TLS → Edge Certificates → Always Use HTTPS**, then **HSTS**. Turn on Always Use HTTPS first, because HSTS only means something over HTTPS.
- Both brands share one `_headers` file because they embed the same two third-party origins. If a brand embeds something else, add its origin to `frame-src` in the CSP line.
- To enforce the CSP, change `Content-Security-Policy-Report-Only` to `Content-Security-Policy` once the browser console shows no reports on every page.

### Checking it

```bash
curl -I https://<domain>/
```

All six headers should appear, and `/_astro/*` files should still return `Cache-Control: public, max-age=31536000, immutable`.

## Adding a brand

1. Copy `src/assets/redcow/` to `src/assets/<brand>/` and replace the content, images, menus and theme. Replace the fonts too — see [Fonts](#fonts).
2. Update `wrangler.jsonc` in the new folder: `name`, `vars`, `allowed_sender_addresses`, `routes`.
3. Onboard the sending domain in Cloudflare Email Service.
4. Create a Worker in Workers Builds with `PUBLIC_BRAND=<brand>`.
