# Testing Guidelines

> Generated by `/install`. Re-run `/clarify testing` any time to refine it further.

## Method

- **Method:** TDD (red → green → refactor). Write the failing test for a new behaviour first, then
  implement until it passes, then refactor with the test green. For changes to code that already
  has tests, apply predict-then-verify (see the `testing` skill) — read the existing tests, predict
  what will/won't break, implement, then compare.

## What we test (coverage philosophy)

- Business logic and boundaries: pure functions in `src/libs`, API route handlers in
  `src/pages/api`, and interactive React island behaviour. Do **not** chase 100% line coverage of
  mid-function implementation details — that's usually wasted effort.
- Static `.astro` markup with no conditional logic is not a test target.

## Test levels

- **Unit:** pure functions in `src/libs/utils`, `src/libs/types` guards/parsers, and any extracted
  logic from `.astro` frontmatter.
- **Component:** React island components (`src/components/client/**`) and hooks, via React
  Testing Library + jsdom.
- **API:** `src/pages/api/**` route handlers (`APIRoute` exports), tested directly against a real
  `Request` and a minimal `APIContext`, in a `node` environment.
- **E2E:** not set up yet. Full page/booking-journey coverage is out of scope until a
  Playwright (or similar) setup is added — don't try to fake it with Vitest.

## Mocking

- Mock at module boundaries (external services — e.g. `src/libs/email`, third-party APIs), not
  internals. Use `vi.mock` / `vi.fn` / `vi.mocked`.
- Keep mock data close to the test, or in a co-located `test-utils.ts` when several tests in a
  slice share it.
- Reset mocks in `beforeEach` (`vi.clearAllMocks()`).

## Libraries & tools

- **Test runner:** Vitest
- **Component testing:** `@testing-library/react`, `@testing-library/user-event`
- **Matchers:** `@testing-library/jest-dom`
- **Environment:** `jsdom` for React islands/hooks, `node` for API routes and `src/libs`
- **Astro components:** no unit-test target for static markup; use the Astro
  [Container API](https://docs.astro.build/en/reference/container-reference/) only for components
  with real conditional rendering logic worth asserting on.

> **Action required (not a workflow-config change):** these are not yet installed. Add as
> devDependencies before the test suite can run:
>
> ```bash
> npm install -D vitest @testing-library/react @testing-library/dom @testing-library/jest-dom jsdom
> ```
>
> Then add a `test` script to `package.json` (e.g. `"test": "vitest run"`) and a `vitest.config.ts`
> (environment: `jsdom`, with a `test/environment` override or per-file `// @vitest-environment
> node` for API-route/lib tests that don't need the DOM). This is intentionally left for a
> follow-up commit — `/install` does not run `npm install`.

## UI components

- React islands are developed and tested in place, co-located with their source
  (`ComponentName.tsx` + `ComponentName.test.tsx`). No Storybook is set up.
